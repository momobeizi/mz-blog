# mz-blog CMS 需求文档

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1 |
| 日期 | 2026-10-21 |
| 产品名称 | mz-blog CMS |
| 形态 | 单站点、单体应用、自托管博客 CMS |
| 后端约束 | Spring Boot 3 + 服务端模板引擎 + MySQL 8 |
| 前台形态 | 服务端渲染的博客站点，面向搜索引擎优化 |
| 后台形态 | React 单页应用，具备前端路由与 RBAC 权限控制 |

## 1. 项目背景与目标

mz-blog 是一个可由个人或小团队自行部署的开源博客内容管理系统。系统需要同时满足两类使用场景：

1. 访客访问公开站点：浏览文章、分类、标签、单页、相册和友情链接，页面应适合 SEO 与移动端阅读。
2. 管理员使用后台：维护内容、前台导航、站点配置以及用户、角色、菜单、字典等系统数据，日常运营不需要修改代码或直接操作数据库。

### 1.1 产品目标

- 内容运营闭环：文章、单页、相册、链接和站点配置均可在后台完成。
- 权限边界清晰：后台菜单、接口权限、按钮权限统一由 RBAC 控制。
- 前后台体验分离：公开站点优先 SEO 与首屏速度；后台优先操作效率与数据安全。
- 可自托管：MySQL 为必需依赖，除本地文件系统外不强制依赖云服务。
- 可扩展：媒体存储、模板、缓存等通过接口隔离，后续可接入对象存储、Redis 和 CDN。

### 1.2 成功标准

- 管理员可在 5 分钟内完成一篇文章的创建、配图和发布。
- 公开文章页在常规网络下首屏可读时间不超过 2.5 秒。
- 普通编辑角色无法访问用户、角色、菜单、字典等系统管理功能。
- 文章下线后公开链接立即不可访问，不出现缓存导致的“已下线仍可见”。
- 站点名称、Logo、备案号、页脚等基础信息修改后无需重启应用。
- 数据库可每日备份，并能在 1 小时内恢复到可用状态。

- 多租户、多站点、多语言站点。
- 评论、审核、回复、敏感词审核。
- 投稿、多人协作审批流、版本对比与回滚。
- 会员体系、付费阅读、订阅与邮件推送。
- 移动 App、微信小程序。
- 全文检索集群、Elasticsearch、对象存储和 CDN 的正式接入。
- 在线主题市场、可视化页面搭建器。

以上能力可在架构上预留扩展点，但不纳入 MVP 验收。

## 3. 用户角色与权限

| 角色 | 使用端 | 权限说明 |
| --- | --- | --- |
| 超级管理员 | 后台 | 拥有全部后台功能；内置角色不可删除、不可停用，至少保留一个启用状态的超级管理员 |
| 内容编辑 | 后台 | 默认可管理文章、分类、标签、单页、相册、媒体、前台菜单和链接；不可管理用户、角色、菜单、字典和核心站点配置 |
| 访客 | 公开站点 | 仅访问已发布内容，不登录、不产生用户数据 |

权限模型采用“用户 → 角色 → 菜单/按钮权限点”的 RBAC 模型。一个用户可拥有多个角色，一个角色可拥有多个后台菜单和按钮权限。最终权限取并集。前端隐藏无权限入口仅用于体验，后端接口必须独立校验权限。

## 5. 功能需求

优先级定义：`P0` 为 MVP 必须完成，`P1` 为首个迭代后的增强项，`P2` 为可选优化。

### 5.1 认证与会话

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| AUTH-001 | 后台账号密码登录 | P0 | 正确账号密码登录成功；错误提示不区分“账号不存在”和“密码错误”；连续失败触发限流 |
| AUTH-002 | 会话保持与超时 | P0 | 刷新页面保持登录；无操作超过 30 分钟自动失效；失效后跳转登录页 |
| AUTH-003 | 退出登录 | P0 | 清理服务端会话；再次访问后台 API 返回未登录 |
| AUTH-004 | 当前用户信息 | P0 | 返回用户基本信息、角色编码、权限编码集合 |
| AUTH-005 | 修改本人密码 | P0 | 校验原密码；新密码需满足复杂度；修改后其他会话失效 |
| AUTH-006 | 个人资料 | P0 | 可修改昵称、头像、邮箱；用户名不可自行修改 |
| AUTH-007 | 登录日志 | P1 | 记录登录时间、IP、User-Agent、成功/失败结果 |

### 5.2 仪表盘

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| DASH-001 | 内容统计 | P0 | 展示文章总数、已发布数、草稿数、单页数、相册数、媒体数 |
| DASH-002 | 最近文章 | P0 | 展示最近更新的 5 篇文章及状态、更新时间 |
| DASH-003 | 最近登录 | P1 | 展示当前用户最近登录时间与 IP |
| DASH-004 | 访问概览 | P1 | 展示近 7 天文章浏览趋势；无统计数据时显示空状态 |

### 5.3 用户管理

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| SYS-USER-001 | 用户列表 | P0 | 支持按用户名、昵称、状态筛选；分页；展示角色和最后登录时间 |
| SYS-USER-002 | 新建用户 | P0 | 用户名唯一且创建后不可修改；密码不少于 8 位；可分配一个或多个角色 |
| SYS-USER-003 | 编辑用户 | P0 | 可修改昵称、邮箱、手机号、头像、备注；用户名不可修改 |
| SYS-USER-004 | 启用/停用 | P0 | 停用后该用户已有会话失效，无法再登录 |
| SYS-USER-005 | 重置密码 | P0 | 管理员可设置新密码；重置后目标用户已有会话失效 |
| SYS-USER-006 | 分配角色 | P0 | 至少保留一个角色；角色变更后权限立即按新角色生效 |
| SYS-USER-007 | 删除用户 | P0 | 不允许删除自己；不允许删除或停用最后一个可用的超级管理员；采用软删除 |

用户字段：用户名、密码、昵称、头像、邮箱、手机号、状态、备注、最后登录时间、最后登录 IP、创建/更新时间。

### 5.4 角色管理

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| SYS-ROLE-001 | 角色列表 | P0 | 展示角色名称、编码、成员数、状态、排序 |
| SYS-ROLE-002 | 新建/编辑角色 | P0 | 角色编码唯一且创建后不可修改；名称和说明可编辑 |
| SYS-ROLE-003 | 分配权限 | P0 | 以树形菜单勾选目录、页面和按钮权限；保存后相关用户权限缓存失效 |
| SYS-ROLE-004 | 启停角色 | P0 | 停用角色后其权限不再生效，用户的角色状态需在权限计算时校验 |
| SYS-ROLE-005 | 删除角色 | P0 | 仍有用户关联时拒绝删除；超级管理员角色不可删除、不可停用、编码不可修改 |

### 5.5 菜单管理（后台）

后台菜单既用于生成 React 侧边栏和路由，也承载按钮级权限点。

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| SYS-MENU-001 | 菜单树 | P0 | 支持多级目录；节点展示名称、类型、路由、权限标识、排序、状态 |
| SYS-MENU-002 | 新建/编辑菜单 | P0 | 类型分为目录、页面、按钮；目录/页面必须有路由；按钮必须有权限标识 |
| SYS-MENU-003 | 路由组件映射 | P0 | 后端返回稳定的 `componentKey`，React 仅从本地组件注册表加载，禁止执行后端下发的任意模块路径 |

| SYS-MENU-006 | 排序与父级 | P0 | 防止把自身或后代设置为父节点，避免循环引用 |

### 5.6 字典管理

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| SYS-DICT-001 | 字典类型 | P0 | 支持类型编码、名称、状态、备注的增删改查；类型编码唯一 |
| SYS-DICT-002 | 字典项 | P0 | 支持标签、值、排序、状态、备注；同类型下值唯一 |
| SYS-DICT-003 | 内置字典保护 | P0 | 文章状态等系统字典不可删除类型，只能维护显示标签和排序 |

### 5.7 文章管理

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| CMS-ARTICLE-001 | 文章列表 | P0 | 支持标题、分类、标签、状态、正文格式、发布时间筛选；支持分页和排序 |
| CMS-ARTICLE-002 | 新建/编辑文章 | P0 | 字段完整；支持自动保存草稿（P1）；编辑已发布文章不会自动下线 |
| CMS-ARTICLE-003 | 双格式正文编辑 | P0 | 创建时可选富文本或 Markdown；富文本支持标题、列表、引用、代码块、表格、链接、图片；Markdown 支持 GFM 常用语法、代码块、表格、任务列表、图片和外链；两种模式均需服务端清洗 |
| CMS-ARTICLE-004 | 封面与摘要 | P0 | 封面上传；摘要为空时从正文纯文本自动截取 120 字 |
| CMS-ARTICLE-005 | 分类与标签 | P0 | 文章必须属于一个分类；可选择多个标签；标签不存在时可在编辑页快捷创建 |
| CMS-ARTICLE-006 | 发布状态 | P0 | 草稿、已发布、已下线；状态切换见 7.3 状态机 |
| CMS-ARTICLE-007 | 置顶与推荐 | P0 | 可独立设置；首页按置顶、推荐、发布时间组合排序 |
| CMS-ARTICLE-008 | SEO 字段 | P0 | 支持 SEO 标题、关键词、描述；为空时回退到文章标题和摘要 |
| CMS-ARTICLE-009 | 预览 | P0 | 登录管理员可在新窗口预览草稿，公开访客不可访问 |
| CMS-ARTICLE-010 | 删除文章 | P0 | 软删除；删除后公开链接立即返回 404；slug 保留，避免旧链接串内容 |
| CMS-ARTICLE-011 | 浏览量 | P1 | 文章详情页访问计数；高并发时可异步批量累加 |
| CMS-ARTICLE-012 | 定时发布 | P1 | 到达指定时间自动发布；失败可重试并有日志 |
| CMS-ARTICLE-013 | 版本历史 | P1 | 保存历史版本并支持回滚 |

文章字段：标题、slug、摘要、封面、正文源内容、正文格式（`HTML`/`MARKDOWN`）、渲染后 HTML、纯文本、分类、标签、作者、状态、置顶、推荐、浏览量、发布时间、SEO 标题、SEO 关键词、SEO 描述、版本号、创建/更新信息。

双格式补充规则：

- 富文本模式保存经过白名单清洗的 HTML；Markdown 模式保存 Markdown 源文，并由服务端渲染为 HTML。
- 公开站点只读取服务端渲染并清洗后的 HTML，不信任浏览器端预览结果。
- 正文格式在创建时选择；已有内容如需切换格式，MVP 不支持直接转换，避免 HTML 与 Markdown 有损互转。P1 可提供明确的格式转换工具并二次确认。
- Markdown 编辑器提供分屏实时预览；最终预览以服务端保存后的预览页为准。
- Markdown 中默认不执行原始 HTML；代码块、表格、任务列表、脚注、自动链接等按 GFM 规则渲染。
- 两种格式生成相同的纯文本摘要、目录和搜索文本；正文中的链接和图片协议仍需校验。

## 6. 前台页面与通用模型

### 6.1 页面公共数据

所有公开页面统一注入以下数据：

- 站点基础配置：名称、Logo、Favicon、备案号、版权信息、社交信息。
- 当前用户：公开站点不使用后台登录态。
- 前台导航树：仅包含启用且可见的菜单。
- 页脚常用链接：按分组和排序输出。
- SEO 默认值：页面未设置时回退到站点默认值。
- 当前年份、站点统计开关等辅助数据。

### 6.2 首页

- 展示站点主视觉、推荐/置顶文章和最新文章。
- 文章卡片包含封面、标题、摘要、分类、发布时间和标签。
- 支持分页或“加载更多”，MVP 采用分页。
- 无文章时展示空状态，不出现服务端错误。

### 6.3 文章详情

- 展示标题、发布时间、更新时间、作者、分类、标签、正文、浏览量。
- 正文支持自动生成目录（P1）。
- 支持上一篇/下一篇或相关文章（P1）。
- 已下线、草稿、删除或不存在的文章统一返回 404。
- 页面包含 canonical、Open Graph、文章结构化数据等 SEO 信息。

### 6.4 搜索

- 仅搜索已发布文章。
- 支持标题和摘要匹配；正文搜索为 P1。
- 空关键词返回提示，不执行全表扫描。
- 结果分页并显示关键词高亮。

## 7. 关键业务规则

### 7.1 内容可见性

- 文章、单页、相册只有 `PUBLISHED` 状态且未删除时才可公开访问。
- 已下线内容立即从列表、详情、站点地图和 RSS 中排除。
- 公开页面不允许通过 URL 参数绕过状态限制。
- 发布文章时必须选择启用状态的分类；分类停用后，对应分类页和导航入口不再公开，但已发布文章的详情仍可访问。需要彻底隐藏文章时应下线文章本身。

### 7.2 Slug 与路径

- slug 仅允许小写字母、数字和连字符，长度 2–80。
- `slug` 在同一内容类型内唯一，创建后默认不可修改；确需修改时旧地址返回 404（不做自动跳转）。
- 中文标题可自动转写为拼音 slug，冲突时追加数字后缀。
- 保留路径不得使用：`admin`、`api`、`assets`、`static`、`uploads`、`articles`、`categories`、`tags`、`pages`、`albums`、`links`、`archive`、`search`、`login`、`sitemap.xml`、`rss.xml`、`robots.txt`。
- 软删除记录仍占用 slug，防止旧链接意外指向新内容。

### 7.3 文章状态机

| 当前状态 | 操作 | 目标状态 | 规则 |
| --- | --- | --- | --- |
| 草稿 | 发布 | 已发布 | 校验必填字段；首次发布写入 `published_at` |
| 已发布 | 下线 | 已下线 | 立即从公开站点移除 |
| 已下线 | 重新发布 | 已发布 | 保留原 `published_at`，更新 `updated_at` |
| 任意未删除状态 | 删除 | 已删除 | 软删除；公开不可见 |
| 草稿 | 删除 | 已删除 | 同上 |

### 7.4 删除与引用

- 用户、角色、菜单、字典、文章、单页、相册、链接均使用软删除或状态停用，具体见数据设计。
- 角色仍被用户引用时不可删除。
- 菜单存在子节点时不可删除。
- 分类存在子分类或文章时不可删除。
- 相册删除时照片记录级联软删除。
- 媒体删除不删除物理文件，避免破坏历史正文中的图片地址。

### 7.5 前台缓存失效

以下操作必须使对应缓存失效：

- 站点配置修改：清除站点配置缓存。
- 前台菜单修改：清除导航缓存。
- 文章发布、下线、删除：清除文章详情、列表、站点地图和 RSS 缓存。
- 分类/标签/相册/链接修改：清除对应模块缓存。
- 字典修改：清除字典缓存。

### 7.6 文件上传

- 默认只允许图片；单文件最大 10MB。
- 文件名由服务端随机生成，保留安全扩展名。
- 存储路径按 `yyyy/MM` 分目录。
- 禁止上传可执行文件、HTML、SVG 和双扩展名绕过文件。
- 上传目录必须禁止脚本执行。
- 富文本和 Markdown 正文中只允许引用本站上传图片或 HTTPS 外链图片。

### 7.7 正文格式与内容安全

- 富文本和 Markdown 都必须经过服务端统一渲染链路，前端编辑器输出不作为可信内容。
- 富文本保存前对 HTML 执行白名单清洗，移除脚本、事件属性、iframe、危险协议和不受支持的样式。
- Markdown 默认转义或移除原始 HTML，再按 GFM 规则渲染；渲染结果仍需经过同一套白名单清洗。
- 允许的标签至少包括段落、标题、列表、引用、代码块、链接、图片、表格、分割线、任务列表。
- 外链统一补充 `rel="noopener noreferrer"`；配置 nofollow 时附加 `nofollow`。
- Markdown 中的图片地址允许本站上传相对地址和 HTTPS 外链；链接仅允许 `http`、`https`、站内相对地址和 `#` 锚点。
- 公开模板对已清洗的渲染结果使用受控 HTML 输出，不允许访客提交 HTML。

## 8. 非功能需求

### 8.1 性能与容量

| 项目 | 目标 |
| --- | --- |
| 内容容量 | 1 万篇文章、500 个单页、100 个相册、2 万张图片 |
| 访问能力 | 50 RPS 公开页面读请求，10 个后台用户同时在线 |
| 公开页面 | 缓存命中时服务端渲染 P95 小于 300ms；首屏可读时间小于 2.5s |
| 后台接口 | 常规列表/详情接口 P95 小于 500ms |
| 上传 | 10MB 图片在 10 秒内完成上传和基础校验 |

### 8.2 安全

- 密码使用 BCrypt 哈希存储，不保存明文、不使用可逆加密。
- 后台所有写操作使用 CSRF 防护；会话 Cookie 设置 `HttpOnly`、`SameSite=Lax`，HTTPS 下设置 `Secure`。
- 登录失败限流；会话固定攻击防护；停用用户或重置密码后清理会话。
- 所有 SQL 使用参数化查询，禁止拼接用户输入。
- 富文本与 Markdown 渲染结果统一白名单清洗；模板输出默认转义，只有已清洗正文允许受控 HTML。
- 上传文件校验扩展名、MIME、文件头、大小和尺寸上限。
- 链接 URL 仅允许 `http`/`https`、站内相对地址和 `#` 锚点；图片仅允许站内相对地址和 HTTPS。
- 生产环境数据库密码、会话密钥等通过环境变量提供，不提交到仓库。
- 后台接口以服务端权限校验为准，不能只依赖前端隐藏菜单。

### 8.3 SEO

- 公开页面服务端渲染，正文和元信息可直接被抓取。
- 每页支持 title、description、keywords、canonical、Open Graph。
- 自动生成 `sitemap.xml` 与 `robots.txt`；可关闭 RSS。
- 文章、单页使用语义化 HTML 和结构化数据。
- 404 页面返回 HTTP 404，下线内容不返回 200 空页面。
- 图片设置 `alt` 和懒加载，缩略图输出明确宽高，降低布局偏移。

### 8.4 可用性与备份

- 单实例部署可接受短暂重启维护；应用重启后数据不丢失。
- 数据库每日全量备份，保留至少 7 天；上传目录每周备份。
- 提供健康检查接口。
- 应用异常返回统一错误页，不向公众暴露堆栈信息。

### 8.5 兼容性与可维护性

- 公开站点支持主流现代浏览器最近两个版本，并适配移动端。
- 后台以桌面端为主，最低支持 1280×720，1024 宽度可横向滚动使用。
- 前端使用 TypeScript；后端使用统一异常、统一响应和统一分页结构。
- 数据库变更通过版本化迁移脚本管理，不手工修改生产库结构。

## 11. 默认决策与假设

为避免需求歧义，MVP 默认采用以下决策：

1. 模板引擎使用 Thymeleaf；公开站点由 Spring Boot 服务端渲染。
2. 后台使用 React + TypeScript + Ant Design，独立构建后由 Spring Boot 在 `/admin` 下提供静态文件。
3. 公开站点与后台同域部署，生产环境通过同一 Spring Boot 应用提供，开发环境由 Vite 代理 API。
4. 认证采用服务端会话 + Spring Security，不使用长期保存在浏览器中的 JWT。
5. 一篇文章属于一个分类，可拥有多个标签。
6. 单页默认 URL 为 `/p/{slug}`；自定义路径不属于 MVP。
7. 图片默认存储在本地文件系统，后续可通过存储接口切换到对象存储。
8. MVP 不包含评论、多租户、审批流、全文检索引擎和邮件服务。
9. MySQL 使用本地 Docker 实例：`127.0.0.1:3306`，数据库 `mz_blog`，本地开发账号 `root/root123`；生产环境必须更换账号并通过环境变量注入密码。
10. 本地已有 Redis 可用于后续缓存，但 MVP 不把 Redis 作为硬依赖。
11. 文章和单页均支持富文本与 Markdown 两种正文格式；创建后格式不可直接切换，MVP 不做有损格式转换。
12. 两种格式均保存源内容和服务端渲染后的 HTML；公开站点只使用渲染并清洗后的 HTML。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 双格式正文 XSS | 后台账号或访客被攻击 | Markdown 原始 HTML 转义、统一白名单清洗、CSP、仅受控模板输出 |
| 上传文件被当作脚本执行 | 服务器被入侵 | 类型/文件头校验、随机文件名、上传目录禁执行、Nginx 隔离 |
| 缓存未及时失效 | 下线内容仍可访问 | 统一缓存键和写操作失效策略，验收覆盖 |
| 动态菜单与前端组件不一致 | 页面白屏或 404 | 后端只下发 `componentKey`，前端维护显式组件注册表 |
| 误删管理员或角色 | 无法登录后台 | 保护最后一个超级管理员，关键删除二次确认 |
| 数据库无备份 | 内容丢失 | 定时备份、恢复演练、迁移脚本版本化 |
